# 문서를 믿기 전에 코드와 대조한다

## 왜 이 스킬이 있나

2026-08-12 에 `ppt/` 문서를 쓰면서 주장을 하나씩 코드와 대조한 결과
**원본 문서 11곳이 틀렸다.** `AS_BUILT_ARCHITECTURE.md` 만 6곳이었다.
그 문서 머리말이 스스로 *"우선순위: 이 문서 < 코드. 충돌하면 코드가 맞다"* 고 적고 있다.

## 먼저 이것부터

```bash
python scripts/verify-docs.py
```

62개 항목을 코드와 대조한다. 종료코드 0 = 전부 통과.
**개수·경로·클래스 존재 여부는 여기서 답이 나온다.** 문서를 뒤지지 말 것.

## 특히 조심할 유형

| 유형 | 왜 위험한가 | 확인법 |
|---|---|---|
| **개수** ("V1–V36", "13종", "테이블 57개") | 가장 자주 낡는다 | `verify.py` |
| **파일·클래스 이름** | 리팩터링으로 사라져도 문서에 남는다 | `grep -rn "<이름>" backend/src ai frontEnd/src` |
| **"~가 금지된다 / ~가 거부한다"** | 기능이 제거돼도 지침만 남는다 | 그 에러 문자열을 코드에서 직접 grep |
| **`Status: TARGET_CANONICAL`** | 목표지 실적이 아니다 | 헤더의 `Implementation Status` 를 본다 |

## 이미 확인된 불일치 11건

`ppt/99_MISSING_MATERIALS.md` **E절** 에 X-01~X-11 로 정리돼 있다.
문서를 인용하기 전에 그 표에 해당 항목이 있는지 본다.

가장 위험했던 것:
- **X-09** — "task input 에 부동소수점 금지, canonical hash 가 거부한다"는 **거짓**이었다
  (9개 문서에 퍼져 있었다). 해셔는 유한 소수를 허용하고, 실제로 막는 것은 **모듈별 입력 계약**이다.
  ⚠ 그렇다고 "이제 소수 써도 된다"가 아니다 — **지침은 유효하고 이유만 틀렸다**
- **X-11** — `TaskRunWorker` 클래스는 **존재하지 않는데** 3개 문서가 그것을 기준으로 절차를 적고 있었다

## 문서를 고칠 때

1. **삭제하지 말고 정정 표시로 남긴다** — `⚠ 2026-08-12 정정: 이 절은 ~라고 적고 있었다. 틀렸다.`
   무엇이 왜 바뀌었는지 추적돼야 다음 사람이 또 안 속는다
2. **지침과 이유를 분리한다.** 이유가 틀렸다고 지침까지 뒤집으면 버그를 만든다(X-09)
3. 숫자나 경로를 바꿨으면 **`scripts/verify-docs.py` 도 같이 고친다.** 안 고치면 FAIL 이 나서 알 수 있다
4. 같은 주장이 여러 문서에 퍼져 있는지 grep 한다 — X-09 는 9곳에 있었다

## 새 사실 주장을 검증에 편입할 때

`scripts/verify-docs.py` 에 `check(이름, 기대값, 실제값)` 한 줄을 더한다.
**기준: 코드/파일에서 기계로 확인 가능한 것만.** 설계 의도·평가·서술은 못 들어간다.
